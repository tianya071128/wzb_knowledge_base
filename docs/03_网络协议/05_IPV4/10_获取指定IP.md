# 获取指定 IP

## DHCP 能否获取指定 IP

分两种场景：客户端主动想要某个 IP；服务器固定分配某个 IP。

### 客户端请求自己想要的 IP

**时机：DHCP‑Request 报文（DORA 流程）**

- 客户端可以在 Request 报文中，通过**选项 50**填写自己希望拿到的 IP 地址。
- 典型场景：[**重启后，客户端希望继续使用上一次的旧 IP**](/ipv4/dhcp.html#快速重连-记忆中有旧-ip)。

重点：**客户端只是 “请求”，没有决定权；最终由 DHCP 服务器决定是否满足。客户端不能强制霸占某个 IP**。

### 服务器静态绑定（MAC‑IP 绑定 / 地址保留）

在 DHCP 服务器（路由器、交换机 DHCP、Windows DHCP 服务）配置：**某 MAC 地址，固定分配指定 IP**

不管客户端请求什么 IP，服务器的 Offer/ACK 始终下发管理员预设的 IP。

- 客户端不需要做特殊配置；
- 只要该 MAC 来申请 DHCP，就拿到固定 IP；
- 就算客户端选项 50 请求别的 IP，服务器依旧给绑定好的 IP。

家用路由器叫：**静态地址分配 / MAC 地址保留**；

企业 DHCP 服务器叫：**保留地址（Reservation）**。

## 静态 IP 配置

**静态 IP（手工静态配置）：手工静态网络配置机制，不属于 DHCP，不属于任何协议。**

### 核心本质

由用户 / 管理员**直接在操作系统网卡上手动填写网络参数**：IP 地址、子网掩码、默认网关、DNS 服务器。

- 不发送任何 DHCP 报文；
- 不依赖 DHCP 服务器；
- 操作系统直接把配置写入网卡，立即生效。

> DHCP 是**动态自动获取机制（应用层协议）**；静态 IP 是**本地手工配置机制**，二者是主机获取 IP 两套互相独立的方案，二选一。

### 和 DHCP 关键对比

| 项目        | 静态 IP（手工配置）                   | DHCP 动态获取                |
| ----------- | ------------------------------------- | ---------------------------- |
| 获取方式    | 用户手动输入保存                      | DHCP 协议报文交互获取        |
| 服务器依赖  | 不需要 DHCP 服务器                    | 必须 DHCP 服务器             |
| 租期        | 无租期，永久有效，直到人为修改 / 删除 | 存在租期，到期需要续约       |
| 报文        | 不会产生 DHCP 任何报文                | DORA、续约等报文             |
| IP 冲突风险 | 高，人为容易重复填同一个 IP           | 服务器地址池管控，冲突概率低 |
| APIPA       | 不会触发 169.254 地址                 | DHCP 失败触发 APIPA          |

静态配置的主机不会与 DHCP 服务器交互，服务器默认并不知道它的存在。如果服务器开启了地址冲突检测，则可在分配某个地址前**感知到该地址已被占用**，从而避免分配。地址池只是服务器的逻辑范围，无法从技术上阻止任何人手动使用其中的 IP。

### IP 冲突

IP 冲突，就是**在同一个广播域（同一个 VLAN/子网）内，两个不同的设备在同一时间配置了完全相同的 IP 地址**。

因为 ARP 协议是根据 IP 来解析 MAC 地址的，当两台主机都声称自己是同一个 IP 时，网络通信就会发生混乱。

**一般都是静态 IP 配置造成的冲突**

#### IP 冲突的具体表现

发生 IP 冲突时，双方设备都会出现异常，典型症状包括：

- **网络时断时续**：数据包被 ARP 表飘移发到错误的 MAC，一会儿通一会儿不通。
- **操作系统弹出冲突提示**：Windows 可能会在右下角冒泡“IP 地址与网络上其他系统冲突”或者直接网络不通，Linux 会在日志中记录 `duplicate IP address detected`。
- **一方被“挤下线”**：有些系统在检测到冲突后会主动禁用网卡或放弃 IP（如 Windows 在收到免费 ARP 冲突后会自行放弃，转为 `169.254.x.x` APIPA 地址）。
- **ARP 表抖动**：在交换机或路由器上查看 ARP 表，同一个 IP 对应的 MAC 地址会反复切换。
- **ping 不通或者严重丢包**。

#### IP 冲突的根本原因

**IP 地址的占有完全是靠“自觉”和“广播宣告”**，没有集中式权威机构强制独占。

- DHCP 服务器只是一个“推荐分配”系统，它没有能力阻止别人手动使用地址池里的 IP。
- 静态配置的电脑只会用 ARP（地址解析协议）去查“谁在用我要配的 IP”（有的操作系统会做免费 ARP 探测），如果发现冲突，系统会报错并可能拒绝使用该 IP；但如果探测失败或对方当时不在线，冲突仍然会在后期同时在线时爆发。
- **最终决定权在操作系统自身**：当收到一个指向自己 IP 的 ARP 请求，或者看到免费 ARP 声称自己是该 IP 时，主机会检查，发现冲突，然后按自己的策略处理（报警、禁用网卡等）。

#### 如何检测 IP 冲突？

1. **主机端主动探测（免费 ARP）**

   在配置静态 IP 时（无论是手动还是系统启动时），主流操作系统都会发送**免费 ARP（Gratuitous ARP）**来探测是否有其他设备正在使用这个 IP。如果有设备响应，系统会报冲突。这是你之前 DHCP 流程中“客户端做免费 ARP”的相同机制。

2. **冲突后的 ARP 分析**

   使用 `arp -a` 查看 ARP 表，如果发现某个 IP 的 MAC 地址频繁变化，很可能发生了冲突。

3. **抓包分析**

   用 Wireshark 过滤 `arp`，你会看到同一个 IP 对应不同的源 MAC 地址，或者系统发出“ARP probe”（目标 IP 全 0，源 IP 为自己）进行探测。

4. **日志查看**

   * Windows 事件查看器：系统日志中会有来源为 “Tcpip” 的事件 ID 4198 或 4199，直接指出冲突的 IP 和 MAC。
   * Linux：`dmesg` 或 `/var/log/messages` 中会有类似 `IPv4: duplicate address detected` 的信息。

#### 预防和解决冲突？

1. **做好 IP 地址规划**

   * 划定 DHCP 地址池范围和静态 IP 范围，**互不重叠**。比如池子是 `.100-.200`，静态设备手动用 `.10-.99`，井水不犯河水。
   * 建立 IP 地址分配台账（或 IPAM 系统），明确哪个 IP 给了哪台设备。

2. **在 DHCP 服务器上做“保留”（Reservation）**

   对于需要固定 IP 的设备（打印机、摄像头、服务器），**不要手动配置**，而是在 DHCP 服务器上将其 MAC 地址与指定 IP 绑定（DHCP Reservation）。这样设备依然用 DHCP 自动获取，但每次拿到的都是同一个静态 IP，且 IP 不会分配给别人，从根本上消除冲突。

3. **开启 DHCP 服务器的冲突检测**

   如我们上题讨论的，在 Windows DHCP 服务器上可以设置“冲突检测次数”，在分配 IP 前先 ping 该地址，如果回应则标记冲突。这能有效防止 DHCP 服务器将已被静态占用的 IP 再分配出去。

4. **利用交换机安全特性**

   * **DHCP Snooping** + **动态 ARP 检测（DAI）**：交换机监听 DHCP 分配过程，建立合法的 IP-MAC 绑定表。如果检测到来自其他 MAC 的 ARP 声称是同一个 IP（比如静态配置了别人的 IP），DAI 会直接丢弃该 ARP 报文，使违规设备网络不通。
   * **IP 源保护（IP Source Guard）**：进一步限制接口只能使用 DHCP 分配的 IP，静态配置的无效。

5. **解决已发生的冲突**

   1. 通过 `arp -a` 或日志，找出冲突 IP 对应的两个 MAC 地址
   2. 在交换机上通过 MAC 地址表定位到两个设备的物理端口
   3. 修改其中一个设备的 IP，使其合规；或将其改成 DHCP 自动获取。

## 对比

| 方式                    | 发起方       | 效果                                | 能否强制拿到            |
| ----------------------- | ------------ | ----------------------------------- | ----------------------- |
| DHCP 选项 50 请求 IP    | 客户端       | 向服务器申请想要的 IP，服务器可拒绝 | ❌不能强制，服务器说了算 |
| DHCP 服务器 MAC‑IP 保留 | 服务器       | 只要该 MAC 接入，一定分配指定 IP    | ✅服务器强制分配         |
| 网卡静态 IP 配置        | 本机操作系统 | 手动写死 IP，不走 DHCP              | ✅完全不受 DHCP 控制     |

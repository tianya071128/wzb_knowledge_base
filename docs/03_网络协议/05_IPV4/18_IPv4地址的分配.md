# IPv4 地址的分配

包含两个层次——**全球公网地址的分配** 和 **本地网络中主机地址的分配**。

## 全球唯一公网 IPv4 地址的分配

在世界范围内，确保每个公网 IP 不重复地被某个机构使用。分配遵循严格的**层级化、逐级分发**模型：

### 第一级：IANA —— 全球互联网的“总部”

**IANA (Internet Assigned Numbers Authority，互联网号码分配机构)** 是整个体系的顶端，负责管理全球 IP 地址池和 DNS 根区。

- **职责**：IANA 不直接给企业或个人分配 IP，而是将巨大的 **/8 地址块**（每个块约 1677 万个 IP）分配给下面的五大 **RIR (区域互联网注册机构)**。
- **现状**：IANA 的 IPv4 地址池早在 **2011年2月3日** 就全部分配完了，再无库存。

### 第二级：RIR —— 五大区域管理机构

全球划分为五个区域，由各自的 RIR 负责本区域内的地址分配和管理。

| 机构                                      | 负责区域                     |
| :---------------------------------------- | :--------------------------- |
| **ARIN** (美国互联网号码注册机构)         | 美国、加拿大及部分加勒比地区 |
| **RIPE NCC** (欧洲IP网络协调中心)         | 欧洲、中东及中亚             |
| **APNIC** (亚太网络信息中心)              | 亚太地区（包括中国）         |
| **LACNIC** (拉丁美洲和加勒比网络信息中心) | 拉丁美洲及加勒比地区         |
| **AFRINIC** (非洲网络信息中心)            | 非洲                         |

- **职责**：RIR 从 IANA 拿到大块地址后，再将其划分为更小的地址块（如 **/12、/16、/22**），分配给下一级的 **NIR (国家互联网注册机构)** 或 **ISP (互联网服务提供商)**。
- **现状**：大部分 RIR 的 IPv4 也已耗尽，只有极少量预留地址或回收地址通过严格的等待队列分配给真正有需求的企业，通常一次只能申请到一个 **/24**（256个IP）甚至 **/22**（1024个IP）。

### 第三级：ISP / 云服务商 —— 运营与分发

这是实际接触公网 IP 的地方。互联网服务提供商（如电信、联通、移动）和大型云服务商（如 AWS、阿里云）从 RIR 或 NIR 申请地址块，再拆分给最终用户。

分配方式分为两类：

1. **静态公网 IP**
   - **场景**：企业宽带、云服务器、网站托管。
   - **特点**：IP 地址固定不变，适合对外提供服务。
   - **分配方式**：申请后手动配置或由云平台绑定。
   - **费用**：通常需要额外付费。IPv4 地址资源稀缺，云厂商甚至会单独收取 IP 闲置费。
2. **动态公网 IP**
   - **场景**：家庭宽带、个人手机热点。
   - **特点**：每次拨号上网，ISP 的 DHCP 服务器会临时分配一个地址给你。地址会周期性变化或重启光猫后就会换一个新 IP。
   - **分配方式**：基于 PPPoE 或 DHCP 协议自动下发。
   - **趋势**：由于公网 IP 枯竭，越来越多的家庭宽带默认只能拿到 **CGNAT（运营商级NAT）** 分配的伪公网 IP。

### 第四级：最终用户 —— 实际的设备

- **家庭用户**：通常你的路由器 WAN 口获取到一个动态公网 IP（如果运营商没强推 CGNAT），内网设备全部通过 NAT 共享这个 IP 上网。
- **企业/云用户**：会拿到一个或多个固定的公网 IP，可以手动配置在服务器网卡上，或者通过云平台的控制台“挂载”到云服务器上。

## 本地网络内 IPv4 地址的分配

指的是在一个局域网（企业或家庭）内部，每台电脑、手机如何获得自己的 IP 地址。

### **DHCP 动态分配（最常见）**

- **工作原理**：路由器或 DHCP 服务器自动从地址池里分配一个私有 IP（如 `192.168.1.5`）给客户端，同时附上子网掩码、默认网关、DNS 等参数。
- **地址池规划**：管理员会在 DHCP 服务器上划定一个范围（如 `192.168.1.100` ~ `192.168.1.200`），避开静态设备和网关的 IP，防止冲突。
- **租约管理**：地址有租期，到期续租或释放，实现动态复用。你学到的 T1/T2 机制就是保障租约续约的关键。

### 静态/手动分配

- **配置方式**：在设备上手动设置 IP、掩码、网关。适用于服务器、打印机、网络设备等需要**固定地址**的节点。
- **与 DHCP 池的关系**：必须避开 DHCP 地址池范围，否则容易发生 **IP 冲突**
- **DHCP 保留（Reservation）**：更优雅的方式是，在 DHCP 服务器上绑定设备的 MAC 地址和特定 IP，使其每次都能“动态”拿到同一个固定 IP，既免去手动配置，又避免冲突。

### NAT 与私有地址复用

- 全球无数个家庭和企业都在同时使用 `192.168.1.0/24` 这样的网段。因为这些**私有地址**不允许出现在公网路由表上，所以不会产生全球性冲突。
- **分配的本质**：私网内的地址分配完全由本地管理员（或家用路由器默认设置）决定，不受全球机构管束。只要同一个局域网内不重复即可。

## IPv4 通过 IP 地址定位位置的逻辑

**可以大致定位，但不能精确到家庭房间；只能定位到运营商的城市 / 区县级别，不能直接定位到具体某台设备的物理地址**。

公网 IP 地址不是随机发放： `IANA互联网编号机构 → 五大RIR区域机构 → 国内APNIC → 国内运营商（联通/电信/移动）→ 省级/地市运营商 → 分配给用户`

每一段 IP 网段，登记在 IP 库（Whois），记录：

- 这个网段属于哪家运营商
- 分配到哪个城市
- 管理联系人

所以拿到一个公网 IPv4，查 Whois，可以看到：归属运营商、所属城市。

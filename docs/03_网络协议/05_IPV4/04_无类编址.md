# 无类编址

无类编址（Classless Addressing）是 IPv4 地址规划的现代标准方案，彻底抛弃了 A/B/C 类固定的网络号边界，**让“网络号”和“主机号”的分界线可以任意滑动**，并通过附加的**子网掩码/前缀长度**来精确告知这条分界线在哪里。

## 诞生背景：有类编址的核心痛点

有类编址中，网络号长度固定为 8/16/24 位，网段粒度只有三种，完全无法匹配真实业务的规模需求，核心问题有三个：

### 1. 地址利用率极低

- 一个 C 类网段仅 254 个可用地址，稍大的部门不够用；
- 申请一个 B 类网段有 65534 个地址，绝大多数场景用不完，90% 以上的地址被闲置浪费；
- 全网整体地址利用率不足 10%，加速了 IPv4 地址枯竭。

### 2. 网络规划极不灵活

企业内部有多个部门、多个办公区，规模大小不一，有类编址无法按需分配网段，要么不够用、要么严重浪费，也无法通过细分网段做广播域隔离、安全隔离。

### 3. 骨干网路由表爆炸

全球数百万个 C 类网段，每个都要在骨干路由器中占一条路由条目，路由器内存、转发性能不堪重负。

### 演进路径

行业分三步完成了从「有类」到「无类」的升级：

1. **子网划分**：在有类地址的主机号中借出若干位作为子网号，把一个大网段拆成多个小网段；
2. **VLSM（可变长子网掩码）**：同一主网段下，不同子网可以使用不同长度的掩码，按需分配地址；
3. **CIDR（无类域间路由）**：彻底抛弃 A/B/C 类概念，用「IP 地址 / 前缀长度」统一表示所有网段，支持跨类路由聚合，大幅压缩路由表。

## 核心基础：子网掩码

### 定义与本质

子网掩码是一个 32 位的二进制数，规则是：

- **网络号（含子网号）部分，二进制全部为 1**
- **主机号部分，二进制全部为 0**

它的唯一核心作用：和 IP 地址做**按位与运算**，提取出 IP 地址的网络号，计算出对应的网络地址。

### 两种标准表示法

#### 方法 1：点分十进制表示

和 IP 地址格式一致，用 4 段十进制数字表示，例如：

- 8 位网络号：`255.0.0.0`
- 16 位网络号：`255.255.0.0`
- 24 位网络号：`255.255.255.0`
- 26 位网络号：`255.255.255.192`

#### 方法 2：CIDR 前缀表示法（主流）

用`IP地址/前缀长度`表示，前缀长度就是网络号的二进制位数，例如：

- `/8` 对应 `255.0.0.0`
- `/16` 对应 `255.255.0.0`
- `/24` 对应 `255.255.255.0`
- `/26` 对应 `255.255.255.192`

前缀表示法更简洁，是现代网络工程的通用写法。

### 核心运算：按位与提取网络地址

**计算规则**：IP 地址 与 子网掩码 逐位做「与运算」（同为 1 则为 1，有一个为 0 则为 0），结果就是网络地址。

#### 分步计算示例

已知：IP 地址 `192.168.1.100`，子网掩码 `255.255.255.0`（/24）

1. 转二进制
   - IP：`11000000 . 10101000 . 00000001 . 01100100`
   - 掩码：`11111111 . 11111111 . 11111111 . 00000000`
2. 逐位与运算
   - 结果：`11000000 . 10101000 . 00000001 . 00000000`
3. 转回十进制
   - 网络地址：`192.168.1.0`
4. 字段拆分
   - 网络号（前 24 位）：`192.168.1`
   - 主机号（后 8 位）：`100`

### 子网掩码的核心功能

#### 本地通信判断：ARP 还是网关？

当电脑 `192.168.1.100/24` 要发给 `192.168.1.200` 时：

- 用自己的掩码 `/24` 算出 `192.168.1.200` 的网络号是 `192.168.1.0`。
- 自己的网络号也是 `192.168.1.0`，**相同 → 对方在同一网络**。
- 直接发 ARP 问 `192.168.1.200` 的 MAC，二层单播送达。

如果发给 `8.8.8.8`：

- 自己的掩码 `/24` 算出 `8.8.8.8` 的网络号是 `8.8.8.0`。
- 自己的网络号是 `192.168.1.0`，**不同 → 对方不在本网**。
- 发 ARP 问**默认网关**的 MAC，交给路由器转发。

**这个判断每时每刻都在你的电脑上发生，依据就是子网掩码。**

#### **子网划分：借位增大网络号**

掩码可以任意滑动。从一个大的私有网段切出多个小子网，本质就是把主机位的前几位改成 `1`，划入网络号部分。

- 原网络：`10.0.0.0/8`（掩码 `255.0.0.0`）
- 借 8 位：`10.0.0.0/16`（掩码 `255.255.0.0`）→ 可分成 256 个 `/16` 子网。

计算公式依旧：

- **子网数** = 2^(借位数)
- **每子网可用主机数** = 2^(剩余主机位数) - 2：减去的这两个地址，分别是**网络地址**和**广播地址**

#### 路由匹配：最长前缀匹配

路由表中每条路由都带掩码。数据包到达时，路由器用掩码算出目的网络号，**谁的前缀最长（掩码中 `1` 最多）、匹配最精确，就选谁**。这是 CIDR 路由聚合的基础。

## 特殊地址

在无类编址体系下，除了普通可分配的主机地址，还有一批具有特殊用途的地址，不能分配给普通主机使用。

### 1. 网络地址（主机号全 0）

每个网段的第一个地址，主机号全为 0，**代表整个网段本身**，不能分配给主机：

```
192.168.1.0/24  → 主机号全 0，是网络地址，不是主机
10.2.0.0/16     → 主机号全 0，是网络地址
```

### 2. 广播地址（主机号全 1）

每个网段的最后一个地址，主机号全为 1，**发给该网段所有主机**，不能分配给主机：

```
192.168.1.255/24  → 主机号全 1，是定向广播地址
10.2.255.255/16   → 主机号全 1，是定向广播地址
```

### 3. 受限广播地址

`255.255.255.255`，不分网段，广播到**本地链路所有主机**，路由器不会转发：

```
应用场景：DHCP 客户端在未获得 IP 时，用 255.255.255.255 发送发现报文
```

### 4. 本机地址（0.0.0.0）

两种含义：

- **作为源地址**：表示“本机、未确定地址”，常见于 DHCP 请求阶段；
- **作为路由条目**：`0.0.0.0/0` 表示默认路由，匹配任意目的地址。

### 5. 回环地址（127.0.0.0/8）

发给本机的流量不离开网卡，用于本地测试和进程间通信：

```
127.0.0.1  → 最常用的 localhost
127.0.0.0/8 整个段都是回环地址
ping 127.0.0.1  → 测试本机 TCP/IP 协议栈是否正常
```

### 6. 私有地址（内网专用）

RFC 1918 规定的三段地址，只能在内部网络使用，**不能在公网路由**，访问公网需经 NAT 转换：

| 地址范围 | CIDR | 可用主机数 |
| --- | --- | --- |
| 10.0.0.0 ~ 10.255.255.255 | 10.0.0.0/8 | ≈1677 万 |
| 172.16.0.0 ~ 172.31.255.255 | 172.16.0.0/12 | ≈104 万 |
| 192.168.0.0 ~ 192.168.255.255 | 192.168.0.0/16 | ≈6.5 万 |

### 7. 组播地址（224.0.0.0/4）

224.0.0.0 ~ 239.255.255.255，一对多通信，不属于单播地址体系：

```
224.0.0.1  → 本地网段所有主机
224.0.0.5  → OSPF 路由器
239.0.0.0/8 → 管理范围内的组播（类似私有地址）
```

### 8. 点对点特殊前缀

- `/31`：只有 2 个地址，不保留网络地址和广播地址，专用于点对点链路（RFC 3021），常见于路由器互联；
- `/32`：单个主机地址，常用于环回接口（loopback）、主机路由。

### 总览

| 特殊地址 | 用途 | 能否分配给主机 |
| --- | --- | --- |
| 主机号全 0 | 网络地址 | ✘ |
| 主机号全 1 | 定向广播 | ✘ |
| 255.255.255.255 | 受限广播 | ✘ |
| 0.0.0.0 | 未确定地址 / 默认路由 | ✘ |
| 127.0.0.0/8 | 回环测试 | ✘ |
| 私有地址段 | 内网专用（需 NAT） | ✔（仅内网） |
| 224.0.0.0/4 | 组播 | ✘ |

# 路由选路

路由选路，就是路由器在收到一个数据包后，决定让它**从哪个接口出去、交给哪个下一跳**的完整决策过程。

## 路由表选路

三大核心原则: ①最长前缀匹配（最高） → ②管理距离（AD / 优先级） → ③度量值 Metric（最低）

### 最长前缀匹配

1. 提取数据包的目的 IP 地址。

2. 用**最长前缀匹配**算法遍历路由表。

   **默认路由前缀是 0，是所有路由里精度最低的，只有其他全部不匹配才轮到它**。

3. 找到匹配的最精确路由条目。

如果**没有任何匹配**（包括没有默认路由 `0.0.0.0/0`），数据包将被丢弃，并回送 **ICMP Type 3（目的不可达）**，具体 Code 取决于场景。

### 管理距离 AD（管理优先级）

作用：评判**路由信息来源的可信度**。 

场景：**同一个目标网段，通过多种途径学到多条路由**（直连、静态、OSPF、RIP）。 

规则：**管理距离数值越小，可信度越高，优先放进路由表生效**。

注意：管理距离是**本地设备概念，不会传递给邻居路由器**，只在本机做选路。

| 路由来源 | 华为优先级 | 思科管理距离 AD |
| -------- | ---------- | --------------- |
| 直连路由 | 0          | 0               |
| 静态路由 | 60         | 1               |
| OSPF     | 10         | 110             |
| IS‑IS    | 15         | 115             |
| RIP      | 100        | 120             |

### 度量值 Metric（开销）

如果管理员同一协议（AD 相同）学来多条去往同一目的的路由，路由器再比较**度量值**。越小越优先。

- **RIP 协议获取的路由信息**：只看跳数。最大 15 跳。
- **OSPF 协议获取的路由信息**：Cost = 累加出接口开销。`Cost = 参考带宽 / 接口带宽`。带宽越大，Cost 越小。

## 策略路由选路

**不单纯看目的 IP**，可以依据源 IP、端口、协议、报文大小等条件，人为指定下一跳 / 出接口，**人为干预转发路径**。

### 与路由表的区别

**策略路由优先级高于内核 IP 路由表。报文先过 PBR，策略没有匹配上，才去查普通路由表。**

| 项目     | 普通路由（IP 路由表）    | 策略路由 PBR                                                 |
| -------- | ------------------------ | ------------------------------------------------------------ |
| 匹配依据 | **只看目的 IP 地址**     | 源 IP、目的 IP、协议、源端口、目的端口、报文长度等 ACL 条件  |
| 查找顺序 | 常规转发逻辑             | **优先级高于普通路由表，先匹配策略路由，不命中才查普通路由表** |
| 生效对象 | 经过设备的所有 IP 报文   | 匹配策略的流量，其余流量走正常路由                           |
| 典型命令 | display ip routing‑table | 策略路由模块，ACL + 流分类 + 下一跳动作                      |

### 策略路由的来源

策略路由来源于**管理员手工配置的策略规则**，由设备的**策略模块（流处理模块）**保存，独立于 IP 路由表。

### 业务场景

1. **内网部分网段走联通，其余走电信**

   - 网段 A：192.168.10.0/24 → 下一跳联通网关
   - 其他所有网段 → 正常路由走电信网关

   使用策略路由，**不看访问的目标 IP，只看源 IP**，实现源地址选路，普通路由做不到。

   普通路由只能根据目的 IP 选路，无法实现 “源 IP 不同走不同外网出口”，这就是 PBR 最大价值。

2. **重要业务报文优先走低延迟专线**

   匹配特定源端口的业务流量，强制走专线下一跳；普通互联网流量走宽带。

3. **测试引流、镜像、报文丢弃**

   匹配特定测试主机流量，转发到测试设备。

## 选路的完整决策链

```text
数据包进入路由器入接口
        │
        ▼
┌─────────────────────┐
│ 1. 是否命中 PBR？   │──是──▶ 按策略转发，跳过路由表
└─────────────────────┘
        │ 否
        ▼
┌─────────────────────┐
│ 2. 查路由表（RIB）  │──无匹配──▶ 丢弃，回 ICMP 不可达
│    最长前缀匹配     │
└─────────────────────┘
        │ 匹配
        ▼
┌─────────────────────┐
│ 3. 多条路由？       │──是──▶ 比 AD → 再比 Metric → 选最优
│    等价多路径？     │        进行负载均衡
└─────────────────────┘
        │ 确定出接口/下一跳
        ▼
┌─────────────────────┐
│ 4. ARP 解析下一跳   │
│    获取目的 MAC     │
└─────────────────────┘
        │
        ▼
┌─────────────────────┐
│ 5. 出向 ACL 检查    │──拒绝──▶ 丢弃
└─────────────────────┘
        │ 允许
        ▼
    封装二层帧，从出接口发出
```

当数据包到达路由器的入接口，转发引擎按以下**优先级**逐一处理：

### 第一步：策略路由（Policy-Based Routing, PBR）—— 最高优先级

在查路由表之前，路由器先检查接口上是否应用了策略路由。PBR 可以**不看目的 IP**，而是根据以下字段来强制指定下一跳或出接口：

- 源 IP 地址
- 入接口
- 协议类型（TCP/UDP）
- 端口号
- 报文大小
- 甚至应用层特征（NBAR 等）

**如果报文匹配了 PBR 策略，就直接按策略转发，不再查路由表。** 

### 第二步：查路由表

如果报文没有被 PBR“截胡”，就进入正常的**路由表查询**。

### 第三步：等价多路径（ECMP）负载均衡

如果路由表中去往同一个目的网络存在**多条开销相同的路径**（管理距离相同、度量值相同），且出自同一个协议，它们都会安装进路由表。此时路由器需要进行**负载均衡**。

思科设备默认支持最多 **4 条**（可配置到 16 条）等价路径。具体报文按哪条路径走，由转发平面的算法决定：

- **逐流（Per-Flow）**：根据源/目 IP、端口等做哈希，同一会话走同一路径，避免 TCP 乱序。这是最常见模式。
- **逐包（Per-Packet）**：轮询分发，可能导致乱序，实际很少用。

### 第四步：ARP 解析下一跳 MAC 地址

选出出接口和下一跳 IP 后，路由器必须知道下一跳的 MAC 地址才能封装二层帧。

- 如果 ARP 缓存里有，直接使用。
- 如果 ARP 缓存没有，发 ARP 请求，获得 MAC 后封装发送。

**注意**：如果出接口是点到点链路（如 PPP、HDLC），则没有 MAC 的概念，直接封装发送。

### 第五步：出向 ACL / 防火墙策略

在报文即将从出接口发出前，接口的出向 **ACL** 或防火墙策略会做最后检查。如果报文被拒绝，它会被丢弃（通常回 ICMP 管理性禁止 `Type 3, Code 13`），而**不是被转发**。

这不是“选路”，但改变了最终的转发结果。

# IP 报文抓包

## 报文详解

![image-20260803151621083](/img/391.png)

### Version（版本）

```plaintext
0100 .... = Version: 4
```

- 4bit 版本字段，`0100`二进制 = 4 → **IPv4**
- 如果是`0110`则为 IPv6。

### IHL（首部长度）

```plaintext
.... 0101 = Header Length: 20 bytes (5)
```

IHL 首部长度（4bit）

- 数值 = 5；**单位：4 字节**

- 5 × 4 = 20 字节

  ✅ 含义：IP 头部为最小长度，**不存在 Options 可选字段**。

  取值范围：5～15，对应头部 20～60 字节。

### DSCP / ECN

```plaintext
Differentiated Services Field: 0x00 (DSCP: CS0, ECN: Not-ECT)
        0000 00.. = Differentiated Services Codepoint: Default (0)
        .... ..00 = Explicit Congestion Notification: Not ECN-Capable Transport (0)
```

旧名称：TOS 服务类型字段（8bit），现在命名为 DS 字段。

- `0000 00.. DSCP=0`：默认业务优先级，普通流量，无 QoS 调度；

- `.... ..00 ECN=0`：报文不支持显式拥塞通知；

  日常局域网通信绝大多数情况为 0x00，几乎不生效。

### Total Length（总长度）

```plaintext
Total Length: 60
```

16bit 字段

**整个 IP 报文总大小 = IP 头部 + IP 载荷（ICMP 报文）一共 60 字节。**

注意：不包含以太网二层头部。

### Identification（标识）

```plaintext
Identification: 0x05bc (1468)
```

标识 ID，16bit。

作用：IP 分片时，**同一个原始数据包的所有分片拥有相同 ID**。

### Flags（标志）

```plaintext
0... .... = Reserved bit: Not set        保留位，恒为0
.0.. .... = Don't fragment: Not set      DF位 = 0
..0. .... = More fragments: Not set      MF位 = 0
```

1. **DF=0（Not set）：允许路由器对数据包分片**

   如果 DF=1，则禁止分片（ping -f 就是置 1）；

2. **MF=0：没有后续分片**

   MF=1 代表后面还有分片；

   结合下方 `Fragment Offset:0` → 该 IP 报文是完整数据包，不是分片！

### Fragment Offset（片偏移）

```plaintext
Fragment Offset: 0
```

片偏移，13bit，单位：8 字节。

用来标记分片数据在原始报文的起始位置。

值为 0 代表：若是分片包，这是第一个分片；本包无分片。

### TTL（生存时间）

```plaintext
Time to Live: 128
```

TTL，生存时间（8bit）

Windows 系统默认初始 TTL=128；Linux 默认 64。

数据包**每经过一台路由器 TTL 自动减 1**；TTL=0，路由器丢弃报文并回复 ICMP 超时。

### Protocol（协议）

```plaintext
Protocol: ICMP (1)
```

上层协议号

### Header Checksum（首部校验和）

```plaintext
Header Checksum: 0x0000 [validation disabled]
```

IP 首部校验和，**只校验 IP 头部，不校验 ICMP 数据**。

> 【常见疑问】为什么显示 0x0000？
>
> Windows 网卡开启**硬件校验和卸载**，由网卡芯片完成校验，操作系统不再填充校验和；
>
> Wireshark 抓取到的报文里此字段填充 0，**不是数据包损坏！**
>
> 标签 `[validation disabled]` 就是说明 Wireshark 不做校验。

### Source Address（源地址）

```plaintext
Source Address: 192.168.7.102
```

发送端 IP

### Destination Address（目的地址）

```plaintext
Destination Address: 192.168.1.209
```

接收端 IP

### Options（选项）

无选项, 大部分情况下都没与选项的

## 本地环回地址(127.0.0.1)

![image-20260803175920790](/img/392.png)

1. **接口是 Loopback 环回接口**

   无以太网帧、无 MAC 地址，流量仅在内核协议栈流转，**不会发送到物理网络**。
   
2. 源 IP 与目的 IP 相同：本机自通信。

3. 虽然不是`127.0.0.1`标准环回地址，但本机 IP 自访问同样走系统环回通路。

4. **IP 报文结构一致**


## 同网段

![image-20260804101123724](/img/393.png)

1. 双方在同一广播域，主机通过 ARP 直接查询 `192.168.7.45` 的 MAC，**直接把帧发给目标电脑，不需要路由器中转**。
2. **IP 报文结构不会区分同网段 / 跨网段！**
3. 同网段、跨网段只是**转发逻辑不同**，三层报文格式一模一样。
4. 同网段:
   1. 数据包：主机 A → 交换机 → 主机 B
   2. **全程不经过路由器，TTL 数值保持 128 不变，不会减 1**
   3. 没有三层路由处理，只有二层交换转发。
5. 跨网段:
   1. 数据包：主机 A → 交换机 → 路由器 → 目标网段交换机 → 主机 B
   2. 数据包经过路由器，**TTL = TTL -1**，IP 首部校验和重新计算。

## 对比

| 报文   | 抓包接口      | 网段关系 | 二层目的 MAC | 转发方式       |
| ------ | ------------- | -------- | ------------ | -------------- |
| 跨网段 | 物理网卡      | 跨网段   | 网关 MAC     | 路由器三层转发 |
| 本地   | Loopback 环回 | 本机自访 | 无 MAC       | 内核内部闭环   |
| 同网段 | 物理网卡      | 同网段   | 目标主机 MAC | 局域网二层直传 |

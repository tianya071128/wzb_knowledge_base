# NAT 网络地址转换

NAT（Network Address Translation，网络地址转换）是 IPv4 地址枯竭时代的“续命”技术。

NAT 的作用就是**让成百上千台使用私有 IP 的设备，能够共享一个或几个公网 IP 来访问互联网**。

**NAT 不是网络协议，是一种 IP 报文转换技术 / 机制**。

## 为什么需要 NAT？

**问题根源**：

- IPv4 地址只有约 43 亿个，完全不够地球上的设备使用。
- 为每一台电脑、手机、服务器都分配一个全球唯一的公网 IP 不现实。

**NAT 的解决思路**：

- **内部**：使用可重复使用的私有 IP 地址（这些地址在公网上无效，但不同组织可以同时使用）。
- **边界**：在连接公网的路由器或防火墙上部署 NAT，当内部设备访问外网时，临时把**私有 IP + 端口**映射成**公网 IP + 端口**，回来时再转换回去。

这样，整个公司或家庭只需要一个公网 IP 就能让所有设备上网，极大地节省了公网地址。

## 公有 IP 地址与私有 IP 地址

**本质区别：能否在全球互联网上路由**：

- **公有 IP 地址**：由 ICANN / 地区性互联网注册机构统一分配，全球唯一。任何一台拥有公有 IP 的设备，理论上可以从互联网的任何一个角落直接访问到它。
- **私有 IP 地址**：在 RFC 1918 中规定，**仅供组织内部使用，不允许出现在公网路由表中**。ISP 路由器收到目的地址为私有 IP 的包，会直接丢弃。

也就是说，你可以随意使用私有 IP，但前提是**只在你的局域网内部**，一旦要上网，必须通过 NAT 转换成公有 IP。

### 私有 IP 地址的三大保留段

RFC 1918 划出了三段专门的地址空间，任何人都可以免费、重复使用：

| 类   | 私有地址范围                      | 默认掩码      | 包含的 CIDR 表示 | 常见使用场景           |
| :--- | :-------------------------------- | :------------ | :--------------- | :--------------------- |
| A 类 | `10.0.0.0` – `10.255.255.255`     | `255.0.0.0`   | `10.0.0.0/8`     | 大型企业、数据中心内部 |
| B 类 | `172.16.0.0` – `172.31.255.255`   | `255.240.0.0` | `172.16.0.0/12`  | 中型网络、部分云 VPC   |
| C 类 | `192.168.0.0` – `192.168.255.255` | `255.255.0.0` | `192.168.0.0/16` | 家用路由器、小型办公室 |

**注意**：`169.254.0.0/16` 是链路本地地址（APIPA），DHCP 失败时系统自动分配，也属于不能上公网的地址，但不属于上述私有地址段。

### 公有 IP 地址的特征

- **全球唯一**：绝不可能有两个组织同时拥有同一个公网 IP。
- **需要申请/购买**：从 ISP 或云服务商那里获取。个人用户通常由运营商动态分配，企业可以购买固定 IP。
- **可以直接被互联网访问**：如果你有一台服务器直接配置了公网 IP，任何互联网用户都可以（在防火墙允许下）直接访问它。
- **地址资源枯竭**：IPv4 公网地址已基本分配殆尽，这就是 NAT 和 IPv6 被极力推广的原因。

## NAT 的基本工作流程

假设电脑（`192.168.1.100`）想访问百度服务器（`110.242.68.66`）。出口路由器 WAN 口有一个公网 IP `1.2.3.4`。

### 出方向：替换源 IP

- 电脑发出的 IP 包：`源 192.168.1.100 → 目的 110.242.68.66`
- 到达路由器后，NAT 把 **源 IP** 从私有地址改成公网地址 `1.2.3.4`，并在 NAT 转换表中记下一笔：`192.168.1.100:端口X ↔ 1.2.3.4:端口Y`。
- 转换后的包发到公网：`源 1.2.3.4 → 目的 110.242.68.66`

### 入方向：还原目的 IP

- 百度的回复包：`源 110.242.68.66 → 目的 1.2.3.4:端口Y`
- 路由器查 NAT 转换表，发现 `1.2.3.4:端口Y` 对应内网的 `192.168.1.100:端口X`，于是把目的 IP 和端口改回去。
- 转换后发给内网：`源 110.242.68.66 → 目的 192.168.1.100:端口X`

从百度的视角看，它以为自己在和 `1.2.3.4` 这台主机通信，完全感知不到内网的存在。这就是 NAT 的核心——**对公网隐藏内部网络结构**。

## NAT 的几种类型

### 静态 NAT（一对一）

- 手动配置内部私有 IP 和公网 IP 的一一对应关系，永久绑定。
- 例如：内网服务器 `192.168.1.10` 永远映射到公网 `1.2.3.4`。
- 好处是外网可以主动访问该服务器（从公网 `1.2.3.4` 发起的连接会被自动转到 `192.168.1.10`）。
- 缺点是需要大量公网 IP，没有节省效果，通常仅用于对外服务。

### 动态 NAT（多对多，先到先得）

- 配置一个公网 IP 池，当内网设备需要上网时，临时分配一个公网 IP 给它，用完后归还。
- 但如果内网设备数多于公网池 IP 数，后来者就拿不到 IP，无法上网。仍然需要多个公网 IP，不适合大规模共享。

### NAPT / PAT（端口地址转换，多对一）

**这就是家用路由器在用的 NAT 类型，也是“NAT”一词最常见的含义。**

- 多个内网 IP 可同时映射到**同一个公网 IP**，通过**不同的源端口号**来区分。
- 转换表记录的是五元组映射：`(内网源IP, 内网源端口, 协议) ↔ (公网IP, 公网端口, 协议)`。
- 例如：
  - 电脑 A：`192.168.1.100:50001` → `1.2.3.4:10001`
  - 手机 B：`192.168.1.101:50002` → `1.2.3.4:10002`
- 一个公网 IP 理论上可以支持 65535 个并发会话(端口号范围：`1‑65535`)，完全满足家庭和小型办公室需求。

## 多层 NAT 转换

根本原因：**IPv4 地址极度匮乏**，运营商都没有足够的公网 IP 给每个用户分配一个。

### 典型场景：家庭宽带的“双重 NAT”

```text
手机 (192.168.1.100)
      │
      ▼
家庭路由器 NAT (192.168.1.1 → 100.64.0.2)   ← 第一次转换
      │
      ▼
运营商 CG-NAT 网关 (100.64.0.2 → 123.45.67.89)  ← 第二次转换
      │
      ▼
      公网互联网
```

**第一层 NAT**：家庭路由器

* 把内网私有 IP `192.168.1.100` 转换成路由器 WAN 口拿到的地址 `100.64.0.2`。

**第二层 NAT**：运营商的 **CGNAT（运营商级 NAT）**

- 运营商给你的路由器 WAN 口分配的并不是真正的公网 IP，而是一个 **ISP 私有地址**（`100.64.0.0/10`，这个地址段专门用于运营商内部）。
- 运营商的 CG-NAT 网关再把你和成千上万个用户的流量，统一转换成少数几个真正的公网 IP。

## NAT 的优缺点与“破坏性”

### 优点

- 极大节省公网 IPv4 地址。
- 隐藏内部网络拓扑，有一定的安全隔离作用（外部无法直接发起对内网设备的连接，除非配置端口映射/静态NAT）。

### 缺点与问题

1. **破坏了端到端通信模型**：互联网初衷是任何主机都可以直接通信，NAT 让内网主机“不可见”，导致一些 P2P 应用、VoIP、在线游戏困难。
2. **额外开销**：路由器需要维护转换表，对每个数据包进行 IP 和端口改写，消耗 CPU 和内存。
3. **与某些协议冲突**：如果应用层数据里携带了内网 IP 地址（如 FTP、SIP），NAT 只改 IP 头而不改应用层载荷，会导致连接失败。需要**NAT ALG**（应用层网关）来辅助修改。
4. **NAT 穿越问题**：两台都在各自 NAT 后面的主机如何直接通信？需要 STUN、TURN、ICE 等技术解决
5. **限制了连接数**：一个公网 IP 的端口有限（65535个），高并发场景可能耗尽端口资源。

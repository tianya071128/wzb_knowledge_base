# 抛出异常

抛出异常是指当程序检测到错误时，主动创建一个异常对象并将其抛出，由调用者处理。

## throw 关键字

使用 `throw` 手动抛出异常：

```java
public void setAge(int age) {
    if (age < 0 || age > 150) {
        throw new IllegalArgumentException("年龄必须在 0-150 之间，当前值：" + age);
    }
    this.age = age;
}
```

### 抛出异常的流程

```
1. 检测到错误条件
2. 创建异常对象（new 异常类）
3. 使用 throw 抛出
4. 当前方法立即终止
5. 查找调用栈中的异常处理器
6. 如果找到匹配的 catch 块，则处理异常
7. 如果未找到，程序终止
```

## throws 关键字

使用 `throws` 声明方法可能抛出的异常，由调用者处理：

```java
// 声明抛出检查异常
public void readFile(String path) throws IOException {
    FileReader reader = new FileReader(path);
    // ...
}

// 调用者必须处理
public static void main(String[] args) {
    try {
        readFile("test.txt");
    } catch (IOException e) {
        System.out.println("读取文件失败：" + e.getMessage());
    }
}
```

### throw vs throws

| 特性 | throw | throws |
|------|-------|--------|
| **位置** | 方法体内 | 方法签名上 |
| **作用** | 抛出异常对象 | 声明可能抛出的异常类型 |
| **数量** | 只能抛出一个异常 | 可以声明多个异常 |
| **语法** | `throw new 异常类()` | `throws 异常类1, 异常类2` |

```java
// throw：方法体内，抛出异常对象
public void checkAge(int age) {
    if (age < 0) {
        throw new IllegalArgumentException("年龄不能为负数");
    }
}

// throws：方法签名上，声明异常类型
public void readFile(String path) throws IOException, FileNotFoundException {
    FileReader reader = new FileReader(path);
}
```

## 常见抛出异常的场景

### 1. 参数校验

```java
public class Person {
    private String name;
    private int age;
    
    public void setName(String name) {
        if (name == null || name.trim().isEmpty()) {
            throw new IllegalArgumentException("姓名不能为空");
        }
        this.name = name;
    }
    
    public void setAge(int age) {
        if (age < 0 || age > 150) {
            throw new IllegalArgumentException("年龄无效：" + age);
        }
        this.age = age;
    }
}
```

### 2. 状态检查

```java
public class Stack<T> {
    private List<T> elements = new ArrayList<>();
    
    public T pop() {
        if (elements.isEmpty()) {
            throw new IllegalStateException("栈为空，无法弹出元素");
        }
        return elements.remove(elements.size() - 1);
    }
    
    public T peek() {
        if (elements.isEmpty()) {
            throw new EmptyStackException();
        }
        return elements.get(elements.size() - 1);
    }
}
```

### 3. 空值检查

```java
public void process(String data) {
    if (data == null) {
        throw new NullPointerException("数据不能为 null");
    }
    // 处理数据...
}

// 或者使用 Objects.requireNonNull（Java 7+）
public void process2(String data) {
    Objects.requireNonNull(data, "数据不能为 null");
    // 处理数据...
}
```

### 4. 不支持的操作

```java
public class ImmutablePoint {
    private final int x;
    private final int y;
    
    public ImmutablePoint(int x, int y) {
        this.x = x;
        this.y = y;
    }
    
    public int getX() { return x; }
    public int getY() { return y; }
    
    // 不可变对象不支持修改操作
    public void setX(int x) {
        throw new UnsupportedOperationException("不可变对象不支持修改");
    }
}
```

### 5. 未实现的抽象方法

```java
public abstract class Shape {
    public abstract double area();
    
    // 提供默认实现，但要求子类必须重写
    public void draw() {
        throw new UnsupportedOperationException("子类必须实现 draw() 方法");
    }
}
```

## 异常链

将一种异常转换为另一种异常，同时保留原始异常信息：

```java
public class UserService {
    public User findUser(int id) throws ServiceException {
        try {
            return userDao.findById(id);
        } catch (SQLException e) {
            // 将底层异常包装为业务异常
            throw new ServiceException("查询用户失败，ID：" + id, e);
        }
    }
}

// 自定义业务异常
public class ServiceException extends Exception {
    public ServiceException(String message) {
        super(message);
    }
    
    public ServiceException(String message, Throwable cause) {
        super(message, cause);  // 保留原始异常
    }
}
```

### 异常链的构造方法

自定义异常时，提供以下构造方法以支持异常链：

```java
public class BusinessException extends RuntimeException {
    // 无参构造
    public BusinessException() {
        super();
    }
    
    // 带消息构造
    public BusinessException(String message) {
        super(message);
    }
    
    // 带消息和原因构造（异常链）
    public BusinessException(String message, Throwable cause) {
        super(message, cause);
    }
    
    // 带原因构造
    public BusinessException(Throwable cause) {
        super(cause);
    }
}
```

### 使用异常链

```java
// 原始异常
try {
    int result = 10 / 0;
} catch (ArithmeticException e) {
    // 包装为自定义异常
    throw new BusinessException("计算失败", e);
}

// 获取原始异常
try {
    // ...
} catch (BusinessException e) {
    System.out.println("业务异常：" + e.getMessage());
    System.out.println("原始异常：" + e.getCause());
}
```

## 异常转换

将一种异常转换为另一种更合适的异常：

```java
// 将检查异常转换为运行时异常
public String loadConfig(String path) {
    try {
        return Files.readString(Path.of(path));
    } catch (IOException e) {
        // 转换为运行时异常，调用者无需强制处理
        throw new UncheckedIOException("读取配置文件失败", e);
    }
}

// 将多种异常转换为统一异常
public void connectDatabase(String url) {
    try {
        // 数据库连接代码
    } catch (SQLException e) {
        throw new DataAccessException("数据库连接失败", e);
    } catch (ClassNotFoundException e) {
        throw new DataAccessException("数据库驱动未找到", e);
    }
}
```

## 重新抛出异常

捕获异常后，可以重新抛出：

```java
// 简单重新抛出
try {
    // ...
} catch (IOException e) {
    // 做一些处理
    logger.error("发生异常", e);
    throw e;  // 重新抛出
}

// 重新抛出时添加信息
try {
    // ...
} catch (IOException e) {
    throw new IOException("读取文件失败：" + path, e);
}
```

### 异常过滤（Java 7+）

在 catch 块中根据条件决定是否重新抛出：

```java
try {
    // ...
} catch (SQLException e) {
    if (e.getErrorCode() == 1045) {
        // 认证失败，不处理
        throw e;
    } else {
        // 其他错误，记录日志
        logger.error("数据库错误", e);
    }
}
```

## 最佳实践

### 1. 使用合适的异常类型

```java
// ❌ 不好：使用过于宽泛的异常
throw new Exception("参数错误");

// ✅ 好：使用具体的异常
throw new IllegalArgumentException("参数错误");
```

### 2. 提供有意义的异常消息

```java
// ❌ 不好：消息不明确
throw new IllegalArgumentException("错误");

// ✅ 好：消息包含上下文
throw new IllegalArgumentException("年龄必须为正数，当前值：" + age);
```

### 3. 不要忽略异常原因

```java
// ❌ 不好：丢失原始异常信息
try {
    // ...
} catch (SQLException e) {
    throw new ServiceException("数据库错误");  // 丢失了 e
}

// ✅ 好：保留原始异常
try {
    // ...
} catch (SQLException e) {
    throw new ServiceException("数据库错误", e);  // 保留 e
}
```

### 4. 尽早抛出异常

```java
// ❌ 不好：延迟发现问题
public void process(String data) {
    // 很多业务逻辑...
    if (data == null) {
        throw new IllegalArgumentException("data 不能为 null");
    }
}

// ✅ 好：方法入口就检查
public void process(String data) {
    Objects.requireNonNull(data, "data 不能为 null");
    // 业务逻辑...
}
```

### 5. 使用标准异常

| 场景 | 推荐异常 |
|------|----------|
| 参数为 null | `NullPointerException` 或 `IllegalArgumentException` |
| 参数值不合法 | `IllegalArgumentException` |
| 参数索引越界 | `IndexOutOfBoundsException` |
| 对象状态不正确 | `IllegalStateException` |
| 不支持的操作 | `UnsupportedOperationException` |
| 需要强制处理 | 自定义检查异常 |

## 注意事项

1. **throw 后面不能有代码**：因为异常会立即终止方法
2. **throws 只是声明**：不一定会真的抛出异常
3. **检查异常必须处理**：要么 try-catch，要么 throws
4. **运行时异常可以不处理**：但应该通过代码逻辑避免
5. **异常消息要清晰**：便于调试和定位问题
6. **保留异常链**：转换异常时不要丢失原始异常

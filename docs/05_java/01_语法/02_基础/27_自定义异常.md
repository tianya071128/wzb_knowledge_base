# 自定义异常

自定义异常是根据业务需求创建的异常类，用于表示特定领域的错误情况。

## 为什么需要自定义异常

1. **表达业务语义**：`UserNotFoundException` 比 `Exception` 更清晰
2. **携带业务数据**：可以添加与业务相关的字段和方法
3. **分层处理**：不同层使用不同异常，便于定位问题
4. **强制处理**：检查异常强制调用者处理

## 自定义异常的基本步骤

### 1. 继承合适的异常类

```java
// 继承 RuntimeException：运行时异常（推荐）
public class BusinessException extends RuntimeException {
}

// 继承 Exception：检查异常
public class BusinessException extends Exception {
}
```

### 2. 提供构造方法

```java
public class BusinessException extends RuntimeException {
    // 无参构造
    public BusinessException() {
        super();
    }

    // 带消息构造
    public BusinessException(String message) {
        super(message);
    }

    // 带消息和原因构造（异常链）
    public BusinessException(String message, Throwable cause) {
        super(message, cause);
    }

    // 带原因构造
    public BusinessException(Throwable cause) {
        super(cause);
    }
}
```

> **建议**：至少提供带消息和带消息+原因的构造方法。

## 运行时异常 vs 检查异常

### 运行时异常（推荐）

```java
public class InvalidAgeException extends RuntimeException {
    public InvalidAgeException(String message) {
        super(message);
    }
}

// 使用：调用者不需要强制处理
public void setAge(int age) {
    if (age < 0 || age > 150) {
        throw new InvalidAgeException("年龄无效：" + age);
    }
}
```

**适用场景**：

- 编程错误（参数校验、状态检查）
- 无法恢复的错误
- Spring/Hibernate 等框架大量使用

### 检查异常

```java
public class UserNotFoundException extends Exception {
    public UserNotFoundException(String message) {
        super(message);
    }
}

// 使用：调用者必须处理
public User findUser(String username) throws UserNotFoundException {
    User user = userDao.findByUsername(username);
    if (user == null) {
        throw new UserNotFoundException("用户不存在：" + username);
    }
    return user;
}

// 调用者必须处理
try {
    User user = findUser("admin");
} catch (UserNotFoundException e) {
    System.out.println(e.getMessage());
}
```

**适用场景**：

- 外部资源操作（文件、网络、数据库）
- 可恢复的错误
- 强制调用者处理

## 带业务数据的异常

自定义异常可以携带与业务相关的字段：

```java
public class OrderException extends RuntimeException {
    private final String orderId;
    private final String errorCode;

    public OrderException(String message, String orderId, String errorCode) {
        super(message);
        this.orderId = orderId;
        this.errorCode = errorCode;
    }

    public String getOrderId() {
        return orderId;
    }

    public String getErrorCode() {
        return errorCode;
    }
}

// 使用
public void cancelOrder(String orderId) {
    Order order = orderDao.findById(orderId);
    if (order == null) {
        throw new OrderException("订单不存在", orderId, "ORDER_NOT_FOUND");
    }
    if (order.getStatus() == OrderStatus.CANCELLED) {
        throw new OrderException("订单已取消", orderId, "ORDER_ALREADY_CANCELLED");
    }
    // 取消订单...
}

// 捕获时获取业务数据
try {
    cancelOrder("ORD123");
} catch (OrderException e) {
    System.out.println("订单ID：" + e.getOrderId());
    System.out.println("错误码：" + e.getErrorCode());
    System.out.println("错误信息：" + e.getMessage());
}
```

## 异常层级设计

可以创建异常基类和子类，形成异常层级：

```java
// 基类异常
public abstract class BaseException extends RuntimeException {
    private final String errorCode;

    protected BaseException(String message, String errorCode) {
        super(message);
        this.errorCode = errorCode;
    }

    public String getErrorCode() {
        return errorCode;
    }
}

// 用户相关异常
public class UserException extends BaseException {
    public UserException(String message, String errorCode) {
        super(message, errorCode);
    }
}

public class UserNotFoundException extends UserException {
    public UserNotFoundException(String username) {
        super("用户不存在：" + username, "USER_NOT_FOUND");
    }
}

public class UserDisabledException extends UserException {
    public UserDisabledException(String username) {
        super("用户已禁用：" + username, "USER_DISABLED");
    }
}

// 订单相关异常
public class OrderException extends BaseException {
    public OrderException(String message, String errorCode) {
        super(message, errorCode);
    }
}

public class OrderNotFoundException extends OrderException {
    public OrderNotFoundException(String orderId) {
        super("订单不存在：" + orderId, "ORDER_NOT_FOUND");
    }
}
```

### 统一异常处理

```java
// Spring 全局异常处理示例
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(UserNotFoundException.class)
    public ResponseEntity<ErrorResponse> handleUserNotFound(UserNotFoundException e) {
        return ResponseEntity.status(HttpStatus.NOT_FOUND)
            .body(new ErrorResponse(e.getErrorCode(), e.getMessage()));
    }

    @ExceptionHandler(OrderException.class)
    public ResponseEntity<ErrorResponse> handleOrder(OrderException e) {
        return ResponseEntity.status(HttpStatus.BAD_REQUEST)
            .body(new ErrorResponse(e.getErrorCode(), e.getMessage()));
    }

    @ExceptionHandler(BaseException.class)
    public ResponseEntity<ErrorResponse> handleBase(BaseException e) {
        return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR)
            .body(new ErrorResponse(e.getErrorCode(), e.getMessage()));
    }
}
```

## 异常设计规范

### 1. 命名规范

| 异常类型     | 命名规范                     | 示例                        |
| ------------ | ---------------------------- | --------------------------- |
| 通用业务异常 | `XxxException`               | `BusinessException`         |
| 具体业务异常 | `Xxx + 错误类型 + Exception` | `UserNotFoundException`     |
| 状态异常     | `Xxx + StatusException`      | `OrderStatusException`      |
| 参数异常     | `Invalid + Xxx + Exception`  | `InvalidParameterException` |

### 2. 设计原则

```java
// ✅ 好的设计
public class UserNotFoundException extends RuntimeException {
    private final String username;

    public UserNotFoundException(String username) {
        super("用户不存在：" + username);
        this.username = username;
    }

    public String getUsername() {
        return username;
    }
}

// ❌ 不好的设计
public class MyException extends Exception {
    // 缺少构造方法
    // 缺少有意义的字段
    // 命名不清晰
}
```

### 3. 异常包装

```java
// 将底层异常包装为业务异常
public class UserService {
    public User findUser(String username) {
        try {
            return userDao.findByUsername(username);
        } catch (SQLException e) {
            // 包装为业务异常，保留原始异常
            throw new BusinessException("查询用户失败：" + username, e);
        }
    }
}
```

## 注意事项

1. **继承合适的类**：根据场景选择 `RuntimeException` 或 `Exception`
2. **提供构造方法**：至少提供带消息和带消息+原因的构造
3. **异常消息要清晰**：包含足够的上下文信息
4. **保留异常链**：包装异常时不要丢失原始异常
5. **不要过度设计**：不要为每个错误都创建异常类
6. **文档化异常**：在方法注释中说明可能抛出的异常

# 类型擦除

## 什么是类型擦除

类型擦除（Type Erasure）是 Java 泛型实现的核心机制。它指的是在编译过程中，泛型类型信息会被移除（擦除），替换为原始类型（Raw Type）或上界类型。

## 类型擦除的工作原理

### 基本擦除规则

```java
// 编译前 - 使用泛型
public class Box<T> {
    private T item;
    
    public T getItem() {
        return item;
    }
    
    public void setItem(T item) {
        this.item = item;
    }
}

// 编译后 - 类型被擦除
public class Box {
    private Object item;  // T 被替换为 Object
    
    public Object getItem() {
        return item;
    }
    
    public void setItem(Object item) {
        this.item = item;
    }
}
```

### 有界类型的擦除

```java
// 编译前 - 有上界的泛型
public class NumberBox<T extends Number> {
    private T number;
    
    public T getNumber() {
        return number;
    }
}

// 编译后 - T 被替换为上界 Number
public class NumberBox {
    private Number number;  // T 被替换为 Number
    
    public Number getNumber() {
        return number;
    }
}
```

### 多重边界的擦除

```java
// 编译前 - 多重边界
public <T extends Comparable<T> & Serializable> void process(T item) {
    // ...
}

// 编译后 - 替换为第一个边界
public void process(Comparable item) {
    // T 被替换为第一个边界 Comparable
}
```

## 类型擦除的影响

### 1. 不能使用基本类型

```java
// 错误 - 不能使用基本类型
Box<int> intBox = new Box<>();  // 编译错误

// 正确 - 必须使用包装类型
Box<Integer> intBox = new Box<>();
```

**原因**：类型擦除后，`T` 被替换为 `Object`，而 Java 中 `Object` 不能引用基本类型。

### 2. 不能创建泛型类型的实例

```java
// 错误
public <T> void create() {
    T item = new T();  // 编译错误
}

// 错误
public <T> void createArray() {
    T[] array = new T[10];  // 编译错误
}
```

**原因**：编译器不知道要创建什么类型的实例。

**解决方案**：使用工厂方法或反射

```java
// 方案1：使用工厂方法
public <T> void create(Supplier<T> supplier) {
    T item = supplier.get();  // 正确
}

// 方案2：使用反射
public <T> T create(Class<T> clazz) {
    try {
        return clazz.newInstance();  // 正确
    } catch (Exception e) {
        throw new RuntimeException(e);
    }
}
```

### 3. 不能创建泛型数组

```java
// 错误
public <T> void createArray() {
    T[] array = new T[10];  // 编译错误
}

// 解决方案1：使用 Object 数组
public <T> T[] createArray(int size) {
    @SuppressWarnings("unchecked")
    T[] array = (T[]) new Object[size];
    return array;
}

// 解决方案2：使用 ArrayList
public <T> List<T> createList() {
    return new ArrayList<>();  // 推荐
}
```

### 4. 泛型类的静态成员不能使用类的类型参数

```java
// 错误
public class Box<T> {
    private static T item;  // 编译错误
    
    public static T getItem() {  // 编译错误
        return item;
    }
}

// 正确 - 静态成员需要自己的类型参数
public class Box<T> {
    private static <E> E getItem() {  // 正确
        return null;
    }
}
```

**原因**：静态成员属于类本身，不属于任何实例，而类型参数是在创建实例时确定的。

### 5. 不能进行泛型类型的类型检查

```java
// 错误
public <T> void check(Object obj) {
    if (obj instanceof T) {  // 编译错误
        // ...
    }
}

// 错误
public <T> void cast(Object obj) {
    T item = (T) obj;  // 警告：未检查的类型转换
}
```

**原因**：类型信息在运行时已经丢失。

**解决方案**：使用 Class 对象

```java
// 正确
public <T> void check(Object obj, Class<T> clazz) {
    if (clazz.isInstance(obj)) {  // 正确
        T item = clazz.cast(obj);
        // ...
    }
}
```

## 类型擦除与多态

### 方法签名的冲突

```java
// 编译错误 - 方法签名冲突
public class Calculator {
    public int add(List<Integer> list) {
        return list.stream().mapToInt(Integer::intValue).sum();
    }
    
    public int add(List<String> list) {  // 编译错误
        return list.stream().mapToInt(Integer::parseInt).sum();
    }
}

// 原因：类型擦除后，两个方法签名相同
// public int add(List list)
```

### 桥方法（Bridge Method）

```java
// 编译前
public class StringComparator implements Comparator<String> {
    @Override
    public int compare(String s1, String s2) {
        return s1.compareTo(s2);
    }
}

// 编译后 - 编译器生成桥方法
public class StringComparator implements Comparator {
    @Override
    public int compare(String s1, String s2) {
        return s1.compareTo(s2);
    }
    
    // 编译器生成的桥方法
    @Override
    public int compare(Object o1, Object o2) {
        return compare((String) o1, (String) o2);
    }
}
```

**作用**：保持多态性，确保泛型接口的方法在类型擦除后仍然可以正确调用。

## 类型擦除的反射问题

### 无法获取泛型类型信息

```java
// 问题示例
public class GenericClass<T> {
    private T item;
    
    public void printType() {
        System.out.println(item.getClass());  // 运行时类型，不是 T
    }
}

GenericClass<String> obj = new GenericClass<>();
obj.printType();  // 输出实际存储对象的类型，不是 "T"
```

### 通过反射获取泛型信息

```java
import java.lang.reflect.ParameterizedType;
import java.lang.reflect.Type;

// 方案1：通过子类获取泛型类型
public abstract class TypeReference<T> {
    private final Type type;
    
    protected TypeReference() {
        Type superclass = getClass().getGenericSuperclass();
        if (superclass instanceof ParameterizedType) {
            this.type = ((ParameterizedType) superclass)
                .getActualTypeArguments()[0];
        } else {
            throw new RuntimeException("Type information lost");
        }
    }
    
    public Type getType() {
        return type;
    }
}

// 使用
TypeReference<List<String>> ref = new TypeReference<List<String>>() {};
Type type = ref.getType();  // List<String>
System.out.println(type);  // java.util.List<java.lang.String>
```

```java
// 方案2：通过字段获取泛型类型
public class FieldGenericType {
    private List<String> stringList;
    
    public void printFieldType() throws Exception {
        Field field = getClass().getDeclaredField("stringList");
        Type type = field.getGenericType();
        
        if (type instanceof ParameterizedType) {
            ParameterizedType paramType = (ParameterizedType) type;
            System.out.println("Raw type: " + paramType.getRawType());
            System.out.println("Type arguments: " + 
                Arrays.toString(paramType.getActualTypeArguments()));
        }
    }
}

// 输出
// Raw type: interface java.util.List
// Type arguments: [class java.lang.String]
```

```java
// 方案3：通过方法获取泛型类型
public class MethodGenericType {
    public void process(List<String> list) {
        // ...
    }
    
    public void printMethodTypes() throws Exception {
        Method method = getClass().getMethod("process", List.class);
        Type[] paramTypes = method.getGenericParameterTypes();
        
        for (Type paramType : paramTypes) {
            if (paramType instanceof ParameterizedType) {
                ParameterizedType pt = (ParameterizedType) paramType;
                System.out.println("Parameter type: " + pt);
            }
        }
    }
}
```

## 类型擦除的实际影响

### 1. 集合操作

```java
// 类型擦除导致的问题
List<Integer> intList = new ArrayList<>();
List<String> strList = new ArrayList<>();

// 运行时类型相同
System.out.println(intList.getClass() == strList.getClass());  
// 输出：true

// 都可以转换为原始类型
List rawList = intList;
rawList.add("string");  // 运行时不会报错
Integer num = intList.get(1);  // 运行时 ClassCastException
```

### 2. 异常处理

```java
// 不能捕获泛型异常
// 错误
public <T extends Exception> void handle() {
    try {
        // ...
    } catch (T e) {  // 编译错误
        // ...
    }
}

// 正确
public <T extends Exception> void handle(Class<T> exceptionClass) {
    try {
        // ...
    } catch (Exception e) {
        if (exceptionClass.isInstance(e)) {
            T typedException = exceptionClass.cast(e);
            // ...
        }
    }
}
```

### 3. 序列化问题

```java
// 泛型类型信息不会序列化
public class GenericBox<T> implements Serializable {
    private T item;
    
    // 序列化时只保存 item 的实际类型信息
    // T 的类型信息不会保存
}
```

## 绕过类型擦除的方法

### 1. 使用类型令牌（Type Token）

```java
public class TypeSafeMap {
    private Map<Class<?>, Object> map = new HashMap<>();
    
    public <T> void put(Class<T> key, T value) {
        map.put(key, value);
    }
    
    public <T> T get(Class<T> key) {
        return key.cast(map.get(key));
    }
}

// 使用
TypeSafeMap typeMap = new TypeSafeMap();
typeMap.put(String.class, "Hello");
typeMap.put(Integer.class, 100);

String str = typeMap.get(String.class);  // 类型安全
Integer num = typeMap.get(Integer.class);
```

### 2. 使用 Super Type Token

```java
public abstract class SuperTypeToken<T> {
    private final Type type;
    
    protected SuperTypeToken() {
        Type superclass = getClass().getGenericSuperclass();
        if (superclass instanceof ParameterizedType) {
            this.type = ((ParameterizedType) superclass)
                .getActualTypeArguments()[0];
        } else {
            throw new IllegalArgumentException("Must be parameterized");
        }
    }
    
    public Type getType() {
        return type;
    }
}

// 使用 - 必须继承
SuperTypeToken<List<String>> token = new SuperTypeToken<List<String>>() {};
System.out.println(token.getType());  // java.util.List<java.lang.String>
```

### 3. 使用 Gson 的 TypeToken

```java
import com.google.gson.reflect.TypeToken;

// Gson 库提供的类型令牌
TypeToken<List<String>> typeToken = new TypeToken<List<String>>() {};
Type type = typeToken.getType();

// 用于 JSON 反序列化
Gson gson = new Gson();
String json = "[\"a\", \"b\", \"c\"]";
List<String> list = gson.fromJson(json, typeToken.getType());
```

## 类型擦除的优势

### 1. 向后兼容

```java
// Java 5 之前的代码仍然可以运行
List list = new ArrayList();  // 原始类型
list.add("item");
String item = (String) list.get(0);  // 需要强制转换
```

### 2. 运行时性能

- 不生成额外的类文件
- 不增加运行时内存开销
- 泛型信息只在编译期存在

### 3. 简化实现

- 不需要为每种泛型类型生成单独的代码
- JVM 不需要特殊支持泛型

## 类型擦除的局限

### 1. 无法在运行时获取类型信息

```java
// 无法实现这样的功能
public <T> void printTypeName() {
    System.out.println(T.class.getName());  // 编译错误
}
```

### 2. 无法创建泛型类型的数组

```java
// 数组和泛型不兼容
List<String>[] array = new List<String>[10];  // 编译错误
```

### 3. 无法进行类型检查

```java
// 无法在运行时检查泛型类型
if (obj instanceof List<String>) {  // 编译错误
    // ...
}
```

## 总结

类型擦除是 Java 泛型的核心实现机制：

**优点**：
- 向后兼容旧代码
- 运行时性能好
- 实现简单

**缺点**：
- 不能使用基本类型
- 不能创建泛型实例和数组
- 运行时无法获取类型信息
- 不能进行类型检查

**应对策略**：
- 使用包装类型代替基本类型
- 使用工厂方法或反射创建实例
- 使用类型令牌保留类型信息
- 使用 Super Type Token 模式

理解类型擦除对于正确使用 Java 泛型至关重要，它帮助我们理解为什么泛型有这些限制，以及如何绕过这些限制。
